1. Abstract

This project presents the design and implementation of SmartCar — an AI-powered autonomous vehicle system built on a Raspberry Pi 3 platform with 1GB RAM. The system demonstrates real-time computer vision capabilities including traffic light detection using HSV color segmentation, PID-based lane following, collision prediction with automatic braking, pedestrian detection with movement prediction, road condition analysis, smart auto-parking, and convoy (follow-me) mode. The vehicle can be controlled through three independent channels: a local web application over WiFi, a Telegram bot for remote control with emergency SOS capabilities, and an MQTT-based cloud relay for internet control from anywhere in the world. The system processes camera frames at the edge (on-device) with sub-100ms latency, demonstrating that intelligent vehicle systems can be implemented on ultra-low-cost hardware (total BOM under INR 5,000) without relying on cloud computing for decision-making. The project also includes driver behavior analysis with safety scoring, accident detection with automatic Telegram alerts, and comprehensive session logging for post-drive analysis.

Keywords: Autonomous Vehicle, Raspberry Pi, Computer Vision, PID Control, IoT, MQTT, Telegram Bot, Edge AI, Collision Detection, Lane Following, Traffic Light Detection

2. Introduction

2.1 Background

The automotive industry is undergoing a paradigm shift with the advent of autonomous driving technology. Companies like Tesla, Waymo, and Cruise have invested billions of dollars in developing self-driving vehicles equipped with advanced sensors including LiDAR, radar arrays, and multi-camera systems powered by high-performance GPU computing platforms. While these systems achieve remarkable results, they remain inaccessible to the average consumer and prohibitively expensive for educational and research purposes.

This project explores the question: Can meaningful autonomous driving capabilities be achieved on ultra-low-cost hardware using only a single camera and open-source software?

2.2 Problem Statement

Current autonomous vehicle development requires expensive hardware (LiDAR sensors costing $5,000+, high-performance computing units at $10,000+) and proprietary software. There is a need for a low-cost, accessible platform that demonstrates core autonomous driving principles for educational purposes and proof-of-concept development.

2.3 Objectives

  • Design and build an autonomous vehicle using only a Raspberry Pi 3 and a single camera
  • Implement real-time traffic light detection using computer vision
  • Develop PID-controlled lane following with black line tracking
  • Create AI-based collision prediction and automatic emergency braking
  • Implement pedestrian detection with movement prediction
  • Build smart auto-parking using visual markers
  • Develop multi-channel remote control (WiFi, Telegram, Cloud)
  • Create driver behavior analysis and safety scoring system
  • Implement accident detection with automatic emergency alerts

2.4 Scope

The project covers the complete pipeline from hardware assembly and wiring to software development, AI integration, IoT connectivity, and cloud deployment. The system operates as a functional prototype demonstrating 6 driving modes, 6 AI features, and 3 control channels.

3. Literature Review

3.1 Autonomous Driving — Industry Landscape

The Society of Automotive Engineers (SAE) defines 6 levels of driving automation (Level 0 to Level 5). Current commercial systems like Tesla Autopilot operate at Level 2-3, requiring driver supervision. Full Level 5 autonomy remains an unsolved challenge. Our SmartCar operates at Level 2 equivalent in controlled environments — lane keeping, traffic signal response, and emergency braking.

3.2 Computer Vision in Autonomous Vehicles

OpenCV (Open Source Computer Vision Library) provides efficient implementations of image processing algorithms. HSV color space segmentation has been proven effective for traffic light detection in controlled lighting conditions (Diaz et al., 2015). PID controllers remain the standard for lane-keeping assist systems due to their simplicity and effectiveness (Zhao et al., 2017).

3.3 Edge AI vs Cloud AI

Edge computing processes data locally on the device rather than sending it to cloud servers. For autonomous vehicles, this is critical because network latency (100-500ms for cloud roundtrip) is unacceptable for safety-critical decisions like emergency braking. Our system processes all AI inference at the edge with sub-100ms latency.

3.4 IoT in Automotive

MQTT (Message Queuing Telemetry Transport) is the de-facto standard for IoT communication, offering lightweight publish/subscribe messaging ideal for constrained devices. Vehicle-to-Everything (V2X) communication enables vehicles to share data with other vehicles, infrastructure, and cloud services.

7. Features & Working

7.1 Driving Modes

Mode 1: Manual Control

The user controls the car in real-time through the web application or Telegram bot. Controls include forward, backward, left, right, and stop. Speed is adjustable via a slider (0-100%). The driver behavior analysis module tracks all commands and generates a safety score.

Mode 2: Line Following

The car autonomously follows a black line on a white surface using PID (Proportional-Integral-Derivative) control. The camera captures the bottom half of the frame, converts it to binary (black line becomes white pixels), finds the line's centroid, and calculates the error from the frame center. The PID controller adjusts left and right motor speeds to minimize this error, providing smooth trajectory tracking.

PID Equation:
correction = Kp × error + Ki × Σerror + Kd × Δerror
Left Speed = Base Speed + correction
Right Speed = Base Speed - correction
Where Kp = 0.4, Ki = 0.0, Kd = 0.2

Mode 3: Traffic Light Detection

The car detects traffic light colors (red, green, yellow) using HSV color space segmentation on the top half of the camera frame. The system uses dual HSV ranges for red (which wraps around the hue spectrum at 0/180 degrees) and single ranges for green and yellow. Morphological operations (opening and closing) reduce noise. The car stops on red, proceeds on green, and slows on yellow.

Mode 4: Auto Pilot

Combines line following and traffic light detection. The car follows the lane while simultaneously monitoring for traffic signals. If a red light is detected, the car stops regardless of line position. On green, the car resumes line following. This demonstrates multi-task computer vision on resource-constrained hardware.

Mode 5: Smart Parking

The car autonomously parks between two green markers. The process follows a finite state machine (FSM) with four phases: Scanning (rotating to find markers), Aligning (centering between markers), Reversing (backing into the spot), and Parked (final state with confirmation buzzer). The LED and buzzer blink at 1-second intervals during parking mode.

Mode 6: Convoy (Follow Me)

The car follows a colored object selected by the user via Telegram. Available colors include red, blue, green, yellow, orange, pink, and white. The system uses HSV color tracking with a PD (Proportional-Derivative) controller for smooth steering. Distance is estimated from the contour area — larger area means closer object, triggering speed reduction.

7.2 AI Safety Features (Active in All Modes)

Collision Prediction & Auto-Brake

The system tracks the growth rate of objects in the camera's center region across consecutive frames. If an object's bounding area grows consistently for 4+ frames (indicating rapid approach), the system calculates Time-to-Collision (TTC) and triggers automatic emergency braking. An instant alert with 2 photos is sent to the Telegram bot.

Pedestrian Detection & Movement Prediction

Using frame differencing with aspect ratio filtering (height > width, characteristic of human silhouettes), the system detects moving objects in the upper-center camera region. Centroid tracking across frames predicts the pedestrian's direction (left, right, approaching, stationary). If approaching, the car auto-stops and sends a Telegram alert.

Accident Detection & SOS

The system maintains a running baseline of normal frame-to-frame changes during driving. An accident is detected when the frame change exceeds 3x the baseline while the motor was running for >1 second. Upon detection: the motor stops immediately, the LED and buzzer flash rapidly, 5 photos are captured at 2-second intervals, and all photos are sent to the owner's Telegram with an "ACCIDENT DETECTED" alert.

Road Condition Analysis

The bottom strip of the camera frame is analyzed using the Laplacian variance method. Smooth surfaces produce low variance, normal surfaces medium variance, and rough surfaces high variance. The system automatically reduces motor speed proportionally (100% for smooth, 80% for normal, 50% for rough surfaces). A 10-frame running average prevents flickering between states.

Driver Behavior Analysis

During manual driving, the system logs all motor commands with timestamps and calculates a driving safety score (0-100). Deductions are made for sharp turns (direction change within 0.5s), hard brakes (stop from high speed within 0.3s), and sudden speed changes (>25% change). The score and statistics are viewable via the Telegram bot.

8.3 Differential Drive System

The SmartCar uses a 4-wheel differential drive configuration. Two left motors are wired in parallel (connected to OUT1/OUT2 of L298N), and two right motors are wired in parallel (connected to OUT3/OUT4). Steering is achieved by varying the speed difference between left and right motor pairs:

9. AI & Machine Learning Modules

9.1 Processing Strategy for 1GB RAM

Running multiple AI modules on a Pi 3 with only 1GB RAM requires careful optimization:

  • Resolution downscaling: All AI processing runs at 160x120 pixels (camera captures at 256x192)
  • Frame skipping: AI processes every 3rd frame (~7 FPS for AI, 10 FPS for camera)
  • ROI selection: Each module processes only relevant image regions (top half, bottom half, center, etc.)
  • No deep learning: All algorithms use classical computer vision (OpenCV), avoiding memory-hungry neural networks
  • Deque buffers: Fixed-size circular buffers prevent memory growth

13. Future Prospects

13.1 Short-Term Enhancements

  • GPS Module Integration: Adding a NEO-6M GPS module (INR 200) would enable real-time location tracking, geofencing, and precise accident location sharing via Telegram.
  • Ultrasonic Sensors: HC-SR04 sensors (INR 50 each) would provide precise distance measurement for parking and obstacle avoidance, complementing the camera-based system.
  • Speed Sign Detection: OCR-based speed limit sign recognition using Tesseract to automatically adjust vehicle speed.
  • Voice Control: Integration of a USB microphone with speech recognition for hands-free vehicle control.
  • Night Vision: IR LED array for camera-based operation in low-light conditions.

13.2 Medium-Term Developments

  • V2V Communication: Multiple SmartCars communicating via MQTT — when Car A detects a red light, it informs Car B behind it to begin braking. The MQTT infrastructure is already in place.
  • TensorFlow Lite Integration: Deploying lightweight neural network models for more accurate object classification (pedestrian vs cyclist vs animal).
  • SLAM (Simultaneous Localization and Mapping): Building a real-time map of the environment for autonomous navigation without predefined tracks.
  • Swarm Robotics: Coordinating multiple vehicles for warehouse-style logistics applications.
  • Predictive Maintenance: Monitoring motor current draw and camera quality degradation to predict component failures.

13.3 Long-Term Vision

  • Full-Scale Vehicle Integration: Adapting the software architecture for real vehicles using more powerful compute platforms (NVIDIA Jetson) while maintaining the same modular design.
  • Cloud Digital Twin: A real-time 3D simulation mirroring the physical vehicle's state, enabling remote monitoring and virtual testing.
  • Edge-Cloud Hybrid AI: Using edge computing for safety-critical decisions (<10ms) while offloading complex scene understanding to cloud GPU clusters.
  • Fleet Management: A centralized dashboard managing multiple SmartCar units for delivery, surveillance, or agricultural applications.
  • Regulatory Compliance: Adapting the system to meet emerging autonomous vehicle regulations and safety standards.

14. Conclusion

This project successfully demonstrates that meaningful autonomous driving capabilities can be achieved on ultra-low-cost hardware using only a single camera and open-source software. The SmartCar system, built on a Raspberry Pi 3 with 1GB RAM, implements six driving modes (Manual, Line Following, Traffic Light Detection, Auto Pilot, Smart Parking, and Convoy), six AI safety features (Collision Prediction, Pedestrian Detection, Road Condition Analysis, Accident Detection, Driver Behavior Analysis, and Follow-Me Tracking), and three independent control channels (Local WiFi, Telegram Bot, and MQTT Cloud).

Key achievements of this project include:

  • Real-time edge AI processing at ~7 FPS for safety-critical decisions with sub-100ms latency
  • Multi-task computer vision — a single camera frame is simultaneously processed for traffic signals, lane position, obstacles, pedestrians, and road conditions
  • True IoT integration — the vehicle can be monitored and controlled from anywhere in the world via the internet
  • Automatic emergency response — accident detection triggers instant alerts with photographic evidence to the owner's phone
  • Total hardware cost under INR 5,000 — approximately 0.1% of commercial autonomous vehicle sensor suites

The project proves that the core principles of autonomous driving — perception, decision-making, and control — are accessible to students and researchers without requiring enterprise-grade hardware. The modular software architecture ensures that each component can be independently improved or replaced, making this an excellent foundation for further research and development in the field of intelligent transportation systems.
